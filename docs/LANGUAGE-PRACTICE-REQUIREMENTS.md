## 0. 先说结论：能不能"流畅"

"流畅"至少要拆成三档，否则这个词没有验收标准：

| 档位 | 体验描述 | 现在能不能做 | 需要什么 |
| --- | --- | --- | --- |
| **L1 轮次对话** | 按住（或说完停顿）→ 松开 → 2-4 秒后听到回应，像对讲机 / 国际电话稍慢一点 | **能。现有技术栈就够** | 加一个"转写 → 回复 → 合成"的**同步**接口；对话按轮存 |
| **L2 准实时对话** | 说完 1-1.5 秒内开始出声，字幕边识别边出，AI 念的时候你可以打断 | **可行，但要做一期新子系统** | WebSocket 双向通道 + 流式 ASR + 流式 LLM + 流式 TTS + 静音检测（VAD）+ 打断处理 |
| **L3 全双工** | 像真人一样随时插话、500ms 内响应 | **现在不建议承诺** | 语音到语音的实时模型、回声消除、打断仲裁；这套供应商组合很难稳定达标 |

**为什么现在不快（具体到代码，不是感觉）**：

1. 一遍回答现在是"录完整段视频 → 分片上传 → 入分析队列 → 调度器**每 15 秒**轮询一次 →
   ffmpeg 抽音轨 → 批量转写 → 评分"（`AnalysisJobService.processPending`）。这条链路是给"复盘"设计的，
   反馈天然是十几秒到分钟级，不可能用来对话；
2. 语音合成是**整段**合成（`SpeechSynthesizer.call`，`sambert-zhixiang-v1`），不是边生成边播；
3. 供应商适配层只暴露"文件进、文本出"和"文本进、整段音频出"（`AsrProvider` / `TtsProvider`），没有流式接口；
4. 前端播放器是"整段音频 + 字幕按播放进度揭示"，没有流式缓冲、没有打断。

**好消息**：SDK 本身已经具备流式能力，只是没用起来。核对过本地依赖（`dashscope-sdk-java 2.15.1`）：

- `Recognition.streamCall(param, Flowable<ByteBuffer>)`、`sendAudioFrame` / `stop` —— 实时识别；
- `SpeechSynthesizer.streamCall(param)` —— 流式合成；`enableWordTimestamp` + `getTimestamps()` —— 字级时间戳。

所以"L2 可行"不是画饼，缺的是**通道与交互**，不是模型能力。

## 1. 语言与语音能力（2026-10-17 已实测）

探针在 `consumer/src/test/java/com/guangge/Interview/language/VoiceCapabilityProbe.java`
（`mvn -B test -Dvoice.probe=true -Dtest=VoiceCapabilityProbe`），
做法是"合成一句 → 再送回 ASR"，另外用真人录音单独验证识别（往返测试分不清"合成念错"和"识别不支持"）。

| 能力 | 结论 | 证据 |
| --- | --- | --- |
| 英语识别 | **可用** | 英文 TTS 音频往返能识别出 `billing` / `latency` |
| 日语识别 | **可用** | 真人录音 `ありがとう` → `ありがとう？`、`アイスクリーム` → `アイスクリーム？`；同一段音频用 `hint=zh` 返回乱码，说明 `ja` 真的生效 |
| 英语合成 | **可用** | `cosyvoice-v2 / longxiaochun_v2` 合成英文后往返最干净；`sambert-*` 也能听懂但口音更重 |
| 日语合成 | **不可用 → 日语已下线** | 所有可用 DashScope 音色都把日语按中文读音念（识别回来是"瞿影先献基叔地切画"）；本机也没有日语系统语音。用户实测"日语完全不可用"，2026-10-17 已从产品里移除（配置与代码结构保留） |

**因此 P1 只上线英语**。英语有两种声音可选（设置页里选）：

- **系统语音（默认）**：浏览器自带的 `en-US` 音色，文字一到就开口，几乎不等待；
- **服务端音色**：`cosyvoice-v2` 合成，音色统一，但要多等约 2 秒（现在改为"点听才合成"，不挡回复）。

日语等有可用的服务端音色（或确认浏览器语音在目标用户机器上可靠）再加回来；
加回来只需要在 `LanguageCatalog` 里补一条配置。

> 数字/日期读法、敬语级别没有单独量化，放到 L2 之前再补测；它们不影响 L1 的链路。

## 2. 范围

### 2.1 P1（L1 轮次对话，建议先做这一期）

1. **语种**：英语（日语暂时下线，见 §1；语言用注册表配置，加回/新增只加配置）；
2. **场景**：每门语言至少 3 个 —— 面试（behavioral）、工作沟通（日报 / 需求澄清）、日常（点单 / 问路）；
3. **对话节奏**：**点一下开始、再点一下结束**（原本写的是按住说话；实现时改成点击切换 ——
   移动端按住时手指一旦滑出按钮就会误取消，点击切换更稳，L2 再换成 VAD 自动断句）；
4. **AI 回应**：每轮 1-2 句、上限 60 个词，**先接话再推进**（不能每轮都像考官提问）；
5. **轮数**：默认 8 轮，上限 20 轮；说满或用户点结束即进入报告；
6. **每轮即时反馈**（不阻塞对话）：这一句最多 2 条 —— 语法 / 用词 / 更地道的说法，附一句中文解释；
7. **结束报告**：流利度、用词、语法、任务完成度 + 3 条可复述的改进句；发音只做"可理解度"粗评（见 §2.3）；
8. **数字人**：沿用现有切帧动画 + 音量驱动嘴型（与语言无关），播放这一轮的回应；
9. **降级**：合成不可用 → 只显示文字并提示；识别不可用 → 允许**手打输入**继续练；
   模型超时 → 这一轮给一句"没听清，再说一次"，不结束会话；
10. **额度**：一轮 = 1 次（转写 + 回复 + 合成打包计 1），沿用现有 `ModelCallGuard`；每场最多 20 轮；
11. **同一账号只留一场进行中**：新开一场时把旧的进行中会话标成 `abandoned`（不是报错挡住用户 ——
    关掉页面再回来就再也开不了新的了）。

### 2.2 P2（L2 准实时，单独一期，P1 验证留存后再上）

- WebSocket 通道（前端 ↔ 后端 ↔ 供应商），音频按 20ms 帧推流；
- 边说边出字幕（partial），说完 300ms 内定稿；
- 回复**首句先合成先播**，后面的句子边生成边播；
- 允许**打断**：AI 念的时候你开口，立刻停止播放并开始识别（barge-in）；
- 静音检测（VAD）替代按住按钮；
- 延迟预算与降级：任一环节超时自动退回 L1 的行为（整段合成 + 按住说话）。

### 2.3 明确不做

| 不做 | 原因 |
| --- | --- |
| 音素级发音打分 | 需要专门的发音评测模型（音素对齐 + 母语者声学模型），现有 ASR 只给文本；P1 只给"可理解度"（有没有让对方听懂），不假装能指出哪个音发错 |
| 语音克隆 / 自定义音色 | 与本需求无关，且涉及肖像与声音授权 |
| 同传 / 翻译模式 | 这是另一个产品（听说读写+翻译），会把范围撑爆 |
| L3 全双工 | 见 §0 |
| 复用现有 `practice_sessions` 存对话 | 现有结构是"一道题一段视频 + 异步评分"，对话是"一轮一段音频 + 同步回复"；硬塞进去会多出一堆永远为空的列，报告口径也会互相污染。**新开 `language_*` 两张表**，复用鉴权、额度、媒体存储、数字人组件 |

## 3. 功能需求（FR-12）

### 3.1 会话与轮次

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-12.1 | 新建会话 | 选语言 + 场景 + 目标（如"30 秒自我介绍"）+ 角色（面试官/同事/店员）；返回开场白与第一个问题 |
| FR-12.2 | 一轮对话 | 上传一段音频（≤60 秒，webm/ogg/wav）→ 返回 `{transcript, replyText, feedback[], audioUrl, round}`；**同步**返回，不能走异步队列 |
| FR-12.3 | 轮数与结束 | 默认 8 轮、上限 20 轮；到数或手动结束后不可再提交 |
| FR-12.4 | 重说本轮 | 未进入下一轮前可重录，旧轮次标记为 `discarded`（不计入报告） |
| FR-12.5 | 跳过 | 允许跳过一轮（记为 `skipped`，报告里不算分） |
| FR-12.6 | 手打降级 | 输入框可代替录音；转写直接使用手打文本，其余链路一致 |

### 3.2 回复质量（模型侧）

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-12.7 | 先接话 | 回应里必须先回应对方说的内容（复述/确认/追问），再推进话题；不能每轮都问新问题 |
| FR-12.8 | 语言纯度 | 目标语言输出；除非用户明确要求，不夹中文（日语场景不夹英语） |
| FR-12.9 | 难度可调 | 初级只用常用 1500 词、短句；中级正常；高级可用习语（场景里选，默认中级） |
| FR-12.10 | 一致性 | 记住本轮会话里已说过的信息（姓名、公司、数字），后文不能自相矛盾 |
| FR-12.11 | 长度 | 每轮 ≤ 60 词 / 2 句；超出截断（对话节奏比信息量重要） |

### 3.3 反馈与报告

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-12.12 | 逐轮反馈 | 每条指出：原句片段 → 更自然的说法 → 一句中文解释；**最多 2 条**，宁可少而准 |
| FR-12.13 | 不打断对话 | 反馈与回应同一次返回，前端**不弹窗**，收在轮次卡片里 |
| FR-12.14 | 结束报告 | 流利度 / 用词 / 语法 / 任务完成度 4 项 + 3 条改进句 + 整段转写；不出现"发音 87 分"这种没有依据的数字 |
| FR-12.15 | 报告可回听 | 每轮音频可回放（保留期内） |
| FR-12.16 | 保留策略 | 音频与转写 7 天（与录像一致），到期自动清理；报告摘要是否长期保留需你决定（见 Q25） |

### 3.4 工程与成本

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-12.17 | 延迟可观测 | 每轮记录 `asr_ms / llm_ms / tts_ms / total_ms`，报告页脚可查（或仅日志） |
| FR-12.18 | 额度 | 每轮占 1 次额度；额度用完时：本轮不发送、给明确提示（与现有 429 文案一致） |
| FR-12.19 | 并发 | 同一账号同时最多 1 场外语会话（防止两个页面互相抢麦） |
| FR-12.20 | 语言可插拔 | 语言 = 一套配置（ASR 语言提示、TTS 音色、提示词、示例），加语言不改代码逻辑 |

## 4. 延迟预算

### 4.1 P1 目标（同步一轮）

| 环节 | 目标（P50） | 说明 |
| --- | --- | --- |
| 录音停止 → 上传完成 | 0.2-0.5s | 单段音频，几十 KB，不需要视频分片 |
| 转写（含 ffmpeg） | 0.6-1.2s | 复用现有 wav 转换；建议直接让浏览器录 16k 单声道，省掉转换 |
| 模型回复 | 0.5-1.5s | 限长 60 词 |
| 合成 + 下发 | 0.5-1.5s | 单句 |
| **合计** | **2-4s（P50）** | P95 ≤ 6s；超过 8s 视为失败并提示重试 |

**实测（2026-10-17）**

| 阶段 | 一轮耗时 | 说明 |
| --- | --- | --- |
| 首版 | **7.5s** | asr 2.2 + llm 3.0 + tts 2.2（配音挡在回复前面） |
| 去掉阻塞配音 | 5.2s | 文字先回，点"听回复"才合成（`tts` 1802ms 记为按需） |
| 对话换成 `qwen-plus` + 160 token + 短提示词 + 历史 4 轮 | 5.3s | 模型本身不是瓶颈（同提示词 REST 也要约 3s，波动明显） |
| 浏览器直录 16k WAV（跳过 ffmpeg） | **4.0s**（波动 4.0-5.6s） | asr **1.68s**（原来是 2.19s），llm 2.3-3.0s（模型端抖动明显） |

所以现在 L1 是"**等 4-5.5 秒**"（取决于模型当时的速度），比首版快约 40-45%。
还能再压的只剩三件事，都不属于 L1 的"改配置"范畴：
① 更小的模型（`qwen-turbo`，质量待评估）；② 让 LLM 先说第一句（就是 L2 的流式）；③ 更快的 ASR 通道（也是 L2）。

### 4.2 P2 目标（流式）

| 指标 | 目标 |
| --- | --- |
| 说完 → 首个回复字（首字节音频） | ≤ 1.2s（P50），≤ 2s（P95） |
| 说完 → 字幕定稿 | ≤ 0.8s |
| 打断响应（停止播放） | ≤ 200ms |
| 单轮超时降级 | 3s 未出首字节 → 退回 P1 行为 |

## 5. 数据与接口

### 5.1 表（迁移 `V11`，已建）

```sql
language_sessions (
  id uuid pk, owner_id varchar(160), language varchar(8),       -- en / ja
  scenario varchar(32), level varchar(16), role_played varchar(32),
  target varchar(200),                                          -- 本轮目标（如"自我介绍 30 秒"）
  status varchar(16),                                           -- active / finished
  turn_count int, max_turns int,
  created_at, finished_at, retention_until,
  report_json text                                              -- 结束报告（含四项分数与改进句）
)

language_turns (
  id uuid pk, session_id uuid fk, idx int,                      -- 第几轮（1 起）
  audio_key varchar(100), audio_content_type varchar(100), audio_ms int,
  transcript text, reply_text text, feedback_json text,
  asr_ms int, llm_ms int, tts_ms int, total_ms int,
  status varchar(16),                                           -- answered / skipped / discarded
  created_at,
  unique(session_id, idx)
)
```

音频走现有 `MediaStorage`（`local` / S3 同一套），key 与练习的录像分开前缀，保留期清理直接沿用 `retention_until` 的定时任务模式。

### 5.2 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/language-options` | 语言、场景、等级、可用音色（能力验证失败的音色要标出来，不能装作可用） |
| `POST` | `/api/v1/language-sessions` | 建会话，返回开场白与第 1 轮 AI 话术 |
| `POST` | `/api/v1/language-sessions/{id}/turns` | multipart 音频（或 JSON 手打文本）→ `{round, transcript, replyText, feedback[], audioUrl, latency}` **同步** |
| `POST` | `/api/v1/language-sessions/{id}/finish` | 生成报告（同步，模型一次调用；失败可用规则兜底） |
| `GET` | `/api/v1/language-sessions/{id}` | 会话 + 全部轮次（回放与报告） |
| `GET` | `/api/v1/language-sessions` | 历史（按语言分组） |
| `DELETE` | `/api/v1/language-sessions/{id}` | 删除会话与音频 |

### 5.3 与现有模块的复用

| 复用 | 不复用 |
| --- | --- |
| `OwnerResolver`（鉴权）、`ModelCallGuard`（额度） | `practice_sessions` 表结构 |
| `MediaStorage`（音频存 S3 / 本地） | `AnalysisJobService`（异步评分；对话必须同步） |
| `LocalAvatarProvider` + `DigitalHuman.vue`（嘴型动画） | 录像分片上传（音频用不到） |
| `LogSanitizer`、错误统一体（`{code,message}`） | 面试报告的 5 维评分口径（对话用 4 项） |

## 6. 前端

**入口**：侧栏新增"外语口语"（与"笔试练习"同级）。P1 只有会话页与报告页，不做花哨的配置向导。

会话页布局（沿用面试间的"数字人 + 内容区"骨架，不新造视觉语言）：

| 区域 | 内容 |
| --- | --- |
| 顶部 | 语言 / 场景 / 轮次进度（3/8）、结束按钮 |
| 左侧 | 数字人（沿用切帧动画）+ 当前 AI 台词字幕 |
| 右侧 | 这一轮的目标提示（可折叠的中文提示）、**按住说话**按钮、麦克风音量条、剩余录音时长 |
| 下方 | 轮次列表：每轮"你说的 / AI 说的 / 2 条反馈"，可点开听音频 |

交互约束：

- 按住说话时按钮有明确的录制态；松手后立刻进入"正在听 / 正在想"两段状态，**不能没有反馈**；
- 录音上限 60 秒，最后 10 秒倒计时；
- AI 播放中允许"重听这一轮"；P2 才有"打断"；
- 移动端：按住说话要能防误触（移动超过 40px 取消），页面下方留出安全区。

## 8. 风险与已知限制

1. **日语识别是最大的不确定项**：如果 `paraformer-realtime-v2` 的 `ja` 效果不好，
   需要换模型（或双供应商），这会影响 P1 的排期与成本 —— 所以放在最前面验证。
2. **英文/日语音色**：现有 `sambert-zhixiang-v1` 是中文音色，硬拿来说外语会露馅；
   换音色要同时确认"能不能流式""是否支持词级时间戳"（P2 要用）。
3. **网络**：2-4 秒的预算是本地网络；跨地域部署要加 CDN / 就近区域，否则会明显变慢。
4. **成本**：一轮 = 转写 + 回复 + 合成，8 轮 ≈ 一次 5 题面试的成本量级；
   额度按轮计更公平，但要在页面上提前写清"这一场大概消耗几次额度"。
5. **发音打分**：只做"可理解度"，不做音素级；报告里不能出现没有依据的细分发音分数。
6. **P2 的复杂度容易被低估**：WebSocket 通道、VAD、打断、回音消除、断线重连，
   每一项都能单独吃掉一周；所以建议 P1 先上线看留存，再决定 P2 的投入。

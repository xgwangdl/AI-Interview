## 0. 一句话结论

**现在做的是"面试训练工具"，真实用户需要的是"求职作战系统"。**

用户不是因为"想练面试"而打开产品，而是因为：

> "我下周三要面这家公司，我只有 5 天，今天该练什么？"

当前产品能回答"怎么练一道题"，但回答不了"我这周该练什么、练到什么程度算够、离拿到 offer 还差什么"。
这就是"用完一次就再也不回来"的根本原因，不是缺少更多 AI 功能。

## 2. 市场在卖什么（拆成四层）

真实产品不是"一个 AI 对话框"，而是四层能力叠起来：

| 层 | 真实产品的内容 | 我们目前 |
| --- | --- | --- |
| **目标层** | 一个岗位一个 Goal：公司、JD、轮次、截止时间、材料清单、下一步 | **完全没有** |
| **内容层** | 公司真题、岗位题库、面经、学习路线、按天计划 | 只有 AI 现生成 + 很小内置题库 |
| **练习层** | 连续面试（可追问、计时、不可逐题重来）、真人/同行模拟、移动端 | 逐题录制、可暂停/重录；无连续模式；移动端未真机验证 |
| **反馈层** | 结构化评分 + 可解释标准 + 改写建议 + 真人反馈 + 进步证据 | 5 维评分 + 示范回答 + 证据时间点；缺可解释校准、转写纠错、真人层 |
| **结果层** | 投递/内推/面试安排/offer 跟踪、社区、课程 | 完全没有 |

我们目前的强项集中在**练习层与反馈层**，而留存与付费真正依赖的是**目标层 + 结果层**。

## 3. 当前产品的真实位置

### 3.1 已经做得比多数毕设好的地方（应保留）

1. **代码真的在 Docker 里跑**：五种题型 + 参考解自检，这是很多同类产品没有的硬能力；
2. **报告能回到视频时间点**：不是一段泛泛的 AI 评语；
3. **错题本 + 单题重练 + 长期分数档案**：有"练到过线"的闭环；
4. **追问链**：同一道题最多两轮，报告能标出追问；
5. **自托管与成本护栏**：额度、Redis 计数、Docker 一键起，具备小规模运营基础；
6. **数字人**：真人素材切帧 + 音量驱动嘴型，演示效果强。

### 3.2 为什么仍然"像毕设"

| 现象 | 根因 |
| --- | --- |
| 用户练完一场就不知道下一步 | 没有"目标"对象，练习是孤立的 |
| 每次都要重新配置岗位/JD | 没有求职档案与岗位库 |
| 题目随机、不可预期 | 没有稳定的题库与公司维度，AI 每次生成不同 |
| 评分看起来"有道理但不敢信" | 没有评分标准解释、没有转写纠错、没有真人校准 |
| 练 5 分钟要等 20 分钟 | 逐题录制 + 异步分析，不是真实面试节奏 |
| 没有理由第二天回来 | 没有每日任务、提醒、连续记录、社交压力 |
| 没法证明"我进步了" | 只有分数曲线，没有 before/after 回答、真实面试结果 |
| 只能自己用 | 没有同学/导师/社群，也没有学校或训练营的批量场景 |

## 4. 差距矩阵（真实场景 → 我们的状态）

优先级定义：**P0 = 不做就不算真实可用；P1 = 决定留存；P2 = 决定规模化/商业化。**

### P0：真实求职者会立刻需要

| # | 需求 | 真实场景中的样子 | 我们目前 | 为什么是 P0 |
| --- | --- | --- | --- | --- |
| P0-1 | **求职目标 / 岗位档案** | 一个岗位一张卡：公司、JD、轮次（OA/一面/HR）、截止日期、材料清单、当前状态 | 无。每次练习临时填岗位 | 没有它，所有练习都是"无目的地练"，也无法做计划 |
| P0-2 | **每日 10 分钟训练计划** | 打开首页："今天练 3 题：1 道项目追问 + 1 道系统设计 + 1 道英语自我介绍" | 无。只有"创建练习" | 降低启动成本，形成习惯；这是留存的第一杠杆 |
| P0-3 | **连续面试模式** | 一场 20-30 分钟不中断：AI 连续问、可追问、计时、不能逐题重来；结束后统一复盘 | 逐题录制、可暂停/重录 | 真实面试没有"重录"；当前模式训练的是"录视频"，不是"面试" |
| P0-4 | **转写纠错** | 评分前允许用户修正 ASR 错字/漏字，再提交评分 | 转写只读 | ASR 错一个字就可能把"回答完整"判成"答偏"，直接摧毁信任 |
| P0-5 | **回答改写与重录（before/after）** | 针对低分题给出改写版，用户可立即重录，报告并列展示两版差异 | 有示范回答，但不能"改写我的答案再重录" | 用户要知道"具体怎么说更好"，而不只是"哪里差" |
| P0-6 | **可解释评分 + 隐私控制** | 评分标准可见、每项有证据；录制前有同意书；可导出/删除全部数据 | 有 5 维分与证据；无同意书、无导出、删除有 | 面试录像属于敏感数据；没有信任就没有真实用户 |
| P0-7 | **手机可用** | 手机浏览器能录、能看报告、能续练；断线可恢复 | 有响应式 CSS，但未做真机验证与移动端录制兜底 | 求职者大量时间在手机上；不能手机用会直接砍掉一半场景 |

### P1：决定"会不会回来"

| # | 需求 | 真实场景中的样子 | 我们目前 | 留存作用 |
| --- | --- | --- | --- | --- |
| P1-1 | **公司/岗位题库与面经** | "字节 Java 后端一面高频 20 题"、"某公司真实面经" | 无；AI 现生成 | 内容确定性 + 搜索流量；用户会为"这家公司"回来 |
| P1-2 | **学习路线 / 多轮模拟** | 从 OA → 技术面 → 系统设计 → HR 面 → 英语面，按周推进 | 视频面试与笔试独立；无路线 | 把一次性练习变成 4-6 周计划 |
| P1-3 | **每日提醒 / 连续记录** | 邮件/微信提醒、连续天数、周报 | 无 | 习惯回路；没有提醒就没有 D7 |
| P1-4 | **真人/同行反馈** | 同学互评、前大厂面试官 1 对 1、训练营助教 | 无 | AI 评分的天花板是"像"，真人给的是"准" |
| P1-5 | **进步证据** | 同一道题 30 天前后对比、分数轨迹、面试通过记录 | 有分数轨迹与错题重练；无 before/after 视频对照 | 让用户"看见自己在变好"，才有付费理由 |
| P1-6 | **求职结果跟踪** | 投递 → 面试 → offer，记录每次真实面试复盘 | 无 | 把练习与结果绑定，产品才有"作战"感 |
| P1-7 | **英语面试模式** | 英文自我介绍、项目追问、行为面 | 有英语口语练习，但不是"面试"场景 | 外企/留学/大厂国际岗的刚需 |

### P2：规模化与商业化

| # | 需求 | 说明 |
| --- | --- | --- |
| P2-1 | **学校/训练营控制台** | 班级、作业、批量报告、就业率看板；Interviewer.AI 明确把"大学就业率"作为卖点 |
| P2-2 | **企业侧结构化面试** | 统一题目、评分卡、候选人对比、ATS 集成；这是 B 端付费核心 |
| P2-3 | **题库运营后台** | 题目版本、公司标签、难度校准、质量审核；没有运营后台，题库无法规模化 |
| P2-4 | **内容社区** | 面经、offer 汇报、同岗位互助；牛客/面试鸭的流量护城河 |
| P2-5 | **移动 App / 小程序** | 推送、碎片化练习、录音体验更好 |

## 5. 粘性诊断：现在的循环 vs 需要的循环

### 5.1 现在的循环（一次性）

```
创建练习 → 录 5 题 → 等分析 → 看报告 → （可能）错题重练 → 结束
```

问题：

- 起点是"我想练"，不是"我有一个明确的面试"；
- 终点是"报告"，不是"下一步行动"；
- 没有时间压力，也没有外部提醒；
- 练习之间不共享上下文（岗位、简历、目标公司每次重填）。

### 5.2 需要的循环（每周回来）

```
录入目标岗位/面试日期
   ↓
系统生成 7 天计划（每天 10-15 分钟，3 道题）
   ↓
每日练习 → 即时反馈 → 改写/重录 → 记录完成
   ↓
周报：哪一维提升、哪一题仍弱、下周计划
   ↓
真实面试结束 → 录入结果/复盘 → 调整计划
   ↓
下一个目标岗位
```

### 5.3 留存的四个杠杆（按性价比排序）

| 杠杆 | 做法 | 预期作用 |
| --- | --- | --- |
| **目标锚定** | 一个岗位一个 Goal，带截止日期和轮次 | 用户有明确理由在 7 天内反复回来 |
| **每日短任务** | 10 分钟 3 题，首页一键开始 | 降低启动成本，形成习惯 |
| **可见进步** | 同题 before/after、分数轨迹、周报 | 提供继续练的正反馈 |
| **外部约束** | 提醒、同学/助教、班级作业 | 把"想练"变成"必须交" |

## 6. 必须做的需求（P0 详细验收）

### P0-1 求职目标（Job Goal）

**数据**：公司、岗位、JD、简历版本、面试轮次、面试日期、状态（准备中/已投递/面试中/已结束）、备注。

**交互**：

- 首页第一屏是"我的目标"，没有目标时引导创建；
- 所有练习从某个 Goal 发起，自动带入岗位/JD/简历；
- Goal 详情页显示：已练题数、覆盖维度、下一步建议、距离面试天数。

**验收**：新建 Goal 后，创建练习不再需要重填岗位/JD；首页能看到"距面试 3 天，今天建议练 3 题"。

### P0-2 每日训练计划

**规则**（先规则后模型，别一上来就做复杂推荐）：

- 每天 3 题：1 道薄弱维度题 + 1 道目标岗位高频题 + 1 道错题/重练；
- 10-15 分钟内可完成；
- 完成后给"今日完成"，中断可续。

**验收**：从首页到开始第一题 ≤ 2 次点击；完成率、D1/D7 可统计。

### P0-3 连续面试模式

**交互**：开始后连续出题、自动计时、追问不打断、不能单题重录；结束才统一转写/评分；
支持"暂停一次"（真实面试也可能被电话打断），但记录暂停次数。

**验收**：一场 5 题连续面试可完整跑通；报告与逐题模式共用同一套评分；用户能感知"这是面试，不是录视频"。

### P0-4 转写纠错

**交互**：报告页每题转写可编辑；保存后触发重新评分（只重算该题）；显示"已人工修正"。

**验收**：修正一个 ASR 错词后，评分与建议随之更新；原始转写仍保留审计。

### P0-5 回答改写 + 重录

**交互**：低分题给"参考改写"（不是泛泛的 sample answer，而是基于用户原话改写）；
用户可一键"照这个重录"，报告并列展示两版。

**验收**：同一题重录后能看到 before/after 两段视频与分数变化。

### P0-6 信任与隐私

**必须有**：

- 录制前同意书（用途、保留期、谁能看）；
- 一键导出我的全部数据（JSON/PDF）；
- 一键删除账号与全部数据；
- 评分标准页（每个维度 0-100 的含义与证据要求）；
- 明确"不做人脸/情绪判断"。

**验收**：新用户首次录制前必须看到同意书；删除后数据库与对象存储均无残留。

### P0-7 手机可用

**范围**：手机浏览器录视频/音频、断点续练、报告可读。

**验收**：iPhone Safari + Android Chrome 各跑通一场 3 题练习；弱网下不丢已录内容。

## 7. 明确不要做的（至少现在）

| 不做 | 原因 |
| --- | --- |
| **实时面试 Copilot（面试时偷偷给答案）** | Final Round AI 这类产品有，但这是作弊工具，会导致用户被公司拉黑；与"训练"定位冲突，也有伦理与法律风险 |
| 人脸/情绪/微表情评分 | 没有可靠科学依据，且涉及生物特征合规；我们已在报告中明确不做 |
| 自研数字人视频生成 | 成本高、收益低；当前切帧动画已够用，先把内容与闭环做好 |
| L3 全双工语音 | 供应商能力与工程复杂度都不匹配当前阶段；L2 都还没打通 |
| 一开始就做企业 ATS | 没有 B 端客户前，投入产出比极低；先用学校/训练营验证 |

## 8. 技术侧的真实差距（上线前必须处理）

| 问题 | 现状 | 风险 | 处理 |
| --- | --- | --- | --- |
| L1 一轮 4-5 秒 | 已完成优化 | 对话感仍不足 | L2 流式（当前卡在实时 ASR 输入） |
| L2 实时识别 | `NO_VALID_AUDIO_ERROR`，默认关闭 | 不能宣称实时 | 改用 duplex `call + sendAudioFrame`，或换识别通道 |
| 2C2G 部署 | 需要 Postgres/Redis/后端/前端同机 | 构建会 OOM、并发低 | 见部署建议：外部 RDS/OSS、jar 部署、swap、关沙箱 |
| 单机调度器 | 分析队列单线程、单实例 | 多实例会重复消费 | 上 Redis 队列/数据库锁；先做单实例限制 |
| 无邮箱验证/找回密码 | 注册即用 | 账号找回、滥用 | P0 上线前补 |
| 无备份/恢复演练 | 只有迁移 | 数据丢失 | 每日 pg_dump + OSS 备份，季度恢复演练 |
| 无压测 | 只有单测 | 不知道 20 人同时用会不会挂 | k6/Artillery 跑 20/50 并发 |
| 无内容审核 | AI 生成题目 | 不当内容/版权 | 题库先审后发；生成题加敏感词与结构校验 |
| 移动端未真机验证 | 只有响应式 CSS | 一半用户用不了 | P0-7 |
| 无 i18n | 中文硬编码 | 海外/外企场景受限 | 先做英文界面文案抽取 |

## 9. 8 周落地路线（建议）

| 周 | 交付 | 验收指标 |
| --- | --- | --- |
| 第 1 周 | Job Goal + 首页"今天练什么"（规则版） | 新用户 2 次点击开始第一题 |
| 第 2 周 | 连续面试模式（5 题、计时、不可逐题重录） | 完整跑通 10 场内部测试 |
| 第 3 周 | 转写纠错 + 单题重评分 | ASR 错词修正后评分变化可见 |
| 第 4 周 | 回答改写 + 重录 + before/after | 同一题两版视频并列 |
| 第 5 周 | 手机端录制与续练 | iPhone/Android 各 5 场通过 |
| 第 6 周 | 题库 v1（200 题，按岗位/公司标签）+ 每日计划接题库 | 计划中的题来自题库而非现生成 |
| 第 7 周 | 提醒 + 周报 + 连续记录 | D7 可统计；邮件提醒可关闭 |
| 第 8 周 | 隐私导出/删除 + 评分标准页 + 压测 | 删除无残留；20 并发 P95 < 3s（非 AI 接口） |

> 8 周后再决定是否做真人反馈、学校控制台或 L2。不要把这些和目标层同时开工。

## 10. 用什么指标判断"有粘性"

上线后只看五个数（其它都是噪音）：

| 指标 | 目标（早期） | 说明 |
| --- | --- | --- |
| 激活率 | ≥ 60% | 注册后 24h 内完成第一场练习 |
| 首场完成率 | ≥ 70% | 开始练习后完成 ≥ 3 题 |
| 周活跃（WAU/MAU） | ≥ 35% | 有目标的人才会回来 |
| 人均每周练习场次 | ≥ 1.8 | 低于 1 说明没有习惯 |
| D7 留存 | ≥ 25% | 求职类产品可接受的早期线 |

如果 D7 < 15%，先别加功能，先访谈 10 个完成过一场的用户：他们为什么不回来。

## 11. 需要你拍板的四个问题

| # | 问题 | 我的建议 |
| --- | --- | --- |
| Q1 | 主要用户是**在校生**还是**社招/转行**？ | 先在校生（校招有明确时间表、学校可批量获客），但产品结构要能扩到社招 |
| Q2 | 走 **B2C 订阅** 还是 **B2B/学校**？ | 先 B2C 验证留存，同时用一个学校/训练营做 B2B 试点；纯 B2C 获客成本高 |
| Q3 | 题库自建还是继续 AI 生成？ | **必须自建 v1**（200-500 题，人工审），AI 只做补充与个性化；没有稳定题库就没有确定感 |
| Q4 | 要不要做真人反馈？ | 先做"同学互评 + 助教抽检"轻模式；1 对 1 真人面试官等有付费客户再做 |

## 12. 最后一句

这个项目现在最值钱的部分不是"数字人"，而是**真实代码判题 + 可回看的证据报告 + 错题重练**。
下一阶段不要把时间花在更炫的 AI 上，而要把这三件事装进一个"**目标 → 每日计划 → 连续面试 → 改写重录 → 周报 → 真实结果**"的闭环里。
闭环成立，数字人才有意义；闭环不成立，数字人只是更贵的演示。

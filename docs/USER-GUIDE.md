# Light-Interview 使用手册

这份文档面向**使用者**：怎么把系统跑起来、怎么完成一场模拟面试、报告怎么读、出问题怎么查。

- 部署与全部环境变量：见 [DEPLOYMENT.md](DEPLOYMENT.md)
- 代码结构与实现原理：见 [ARCHITECTURE.md](ARCHITECTURE.md)
- 当前完成度与验收证据：见 [STATUS.md](STATUS.md)

---

## 1. 系统能做什么

一个面向求职者的**视频模拟面试系统**。一场练习的完整链路是：

1. **AI 出题**：按岗位、公司、JD、简历生成面试题（也可以自己出题）；
2. **浏览器录制**：逐题作答，摄像头 + 麦克风录制，支持重录；
3. **自动复盘**：后台把录像转成文字（Paraformer 转写），再由大模型按固定 JSON 结构评分（Spring AI）；
4. **结构化报告**：综合得分、5 个维度评分、语速/停顿/口头禅、改进建议、优秀回答示例，以及可点击跳转的视频证据。

数字人面试官会用 TTS 把题目读出来；合成不可用时自动降级为「头像 + 字幕」，不影响作答。

## 3. 启动系统

### 3.1 准备配置

```bash
cp .env.example .env
```

编辑 `.env`，**至少**填两项：

```dotenv
Ali_API_KEY=你的百炼Key
AUTH_TOKEN_SECRET=换一串足够长的随机字符串
```

`.env` 已被 `.gitignore` 忽略，不会进版本库。后端启动时会自动加载仓库根目录（或 `consumer/` 目录）
下的 `.env`，**不需要手动 `export`**。

### 3.2 启动基础设施

```bash
docker compose up -d
docker compose ps        # 三个容器都应是 healthy / Up
```

### 3.3 启动后端

```bash
mvn -B clean package
java -jar consumer/target/consumer-0.0.1-SNAPSHOT.jar
```

启动成功会看到 `Started ConsumerApplication`，端口 8088。首次启动会自动执行数据库迁移。

> 想用热重载做开发：先跑一次 `mvn -B install -DskipTests`，再用 `mvn -pl consumer spring-boot:run`。
> 直接跑后者会因为只构建 consumer 模块、拿到本地仓库里过期的 `common` 而报
> `NoClassDefFoundError: com/guangge/Interview/vo/CvRequest`。

### 3.4 创建登录账号

直接在登录页点「注册」，填用户名 + 密码即可，注册成功会自动登录（密码至少 6 位）。
用户名允许中文、字母、数字与 `_ . -`，长度 2–80。需要批量造账号时也可以用 SQL：

```bash
docker compose exec -T postgres psql -U postgres -d interview \
  -c "INSERT INTO candidates (candidate_name, invitation_code, status) VALUES ('demo','123456',1);"
```

这样插入的是**明文口令**，仍然可以登录；首次登录成功后后端会自动把它改写成 BCrypt 哈希，
不需要人工迁移。

### 3.5 启动前端

```bash
cd web
npm install
npm run dev
```

浏览器打开 <http://localhost:5173>，用刚创建的账号登录。

### 3.6 没有 API Key 的演示模式

把两个供应商都切成本地兜底实现，就能在没有云端凭证时跑通整条链路：

```dotenv
PRACTICE_ASR_PROVIDER=stub
PRACTICE_EVALUATION_PROVIDER=stub
PRACTICE_ANALYSIS_INITIAL_DELAY_MS=2000
PRACTICE_ANALYSIS_POLL_INTERVAL_MS=2000
```

兜底模式会生成一段占位转写并给出示例评分，用于验证界面与流程。
注意：**`Ali_API_KEY` 仍要填一个非空值**——遗留的 AI 组件在启动时会校验它，留空应用起不来。

## 4. 登录

- 登录方式是**用户名 + 密码**，校验 `candidates` 表；密码以 BCrypt 哈希保存，管理员看不到原文；
- 没有账号时在同一个页面切到「注册」页签，注册成功即刻进入工作台；
- 登录成功后在浏览器 `localStorage` 保存 token，后续请求自动带上；
- 同一用户名连续失败 **10 次**会被锁定 **15 分钟**（`AUTH_LOGIN_MAX_ATTEMPTS` /
  `AUTH_LOGIN_LOCK_WINDOW_MINUTES` 可调）。

演示账号：`smoke / 123456`。

## 5. 界面使用

### 5.1 工作台 `/`

入口页：显示历史练习概览，可新建练习或继续未完成的练习。

### 5.2 新建练习 `/practice/setup`

填写本次练习的背景信息，这些内容会作为出题与评分的上下文：

| 字段 | 说明 |
| --- | --- |
| 岗位 / 公司 | 目标职位与公司 |
| 职位描述（JD） | 粘贴 JD，AI 会据此出题 |
| 简历 | 支持上传 PDF / Word，自动抽取文本；也可直接粘贴 |
| 面试类型 | technical / behavioral 等 |
| 难度 | 标准 / 进阶等 |
| 面试官风格 | balanced 等 |
| 题量、时长 | 题目数量与预计时长 |

点「AI 出题」会调用 `POST /api/v1/practice-sessions/question-plan`，按岗位与 JD 生成题目；
你也可以直接手写题目。注意：**创建练习时题目必须与题量一致**，否则接口返回 400。

### 5.3 设备检测 `/practice/device-check`

检查摄像头与麦克风是否可用。浏览器会弹出授权申请，建议在这里先确认设备正常，
避免录到一半才发现权限没给。

### 5.4 面试间 `/practice/:id/session`

逐题循环：

1. 数字人播报题目（TTS 可用时出声，不可用则只显示字幕）；
2. 点录制开始作答，停止后自动上传；
3. 不满意可以**重录**，以最后一次为准；
4. 全部答完提交，结束整场练习。

断网或上传失败时，录像会先存在浏览器本地，恢复后自动补传——不会因为网络抖动丢作答。
录像超过 4MB 时走**分片上传**：只重传缺失的分片，刷新页面后也能接着传，不用从头再来。
每道题上传完就立即进入转写与评分，不必等整场练习结束。

提交整场练习有两个前置条件：**至少完成 1 题**，且**所有已录题目的上传都已结束**。

### 5.5 报告 `/practice/:id/report`

练习提交后进入分析：

- `awaiting_analysis`：还没有可用的分析供应商；
- `pending` / `processing`：后台正在转写与评分；
- `ready`：报告生成完成；
- `analysis_failed`：分析失败，页面上会出现**重试分析**按钮（`POST /api/v1/practice-sessions/{id}/analysis/retry`）。

报告页左侧是逐题视频回放与**回答转写**，可以点击证据里的时间点把视频跳到对应位置；
右侧是本题评分、表达指标、改进建议与优秀回答示例。

**让面试官把示范回答念出来**：优秀回答示例那一栏是「左边小人、右边按钮、下面是字幕」。
**一开始不显示示范回答**（只有一句提示），点右边的「让它回答」，小人开始作答、字幕跟着朗读一句句出现，
**念完整段才显示完整的示范回答**。想中途停下来直接读全文，点「停止」即可。

语音合成第一次点需要等 3-5 秒（按钮显示「准备中…」），之后同一题走浏览器缓存。
合成不可用时会把完整文字直接放出来（不会让你既听不到也看不到）；
示范回答较长时语音只念**前半段**（单次合成有长度上限），此时字幕与语音一致，念完再补上完整文字。

### 5.6 历史 `/history`

查看历史练习与报告入口。超过保留期的练习会被自动清理。

### 5.7 笔试练习（`/coding`）

除了视频面试，系统还有一套独立的**笔试模块**，入口在左侧导航「笔试练习」。

**出题**：填目标岗位（必填）、公司、JD、难度，然后用「+ 上机编程 / + 数据库题 / + 编程填空 /
+ 选择题 / + 简答题」拼出题目组合，点「生成题目并开始」。出题过程：

1. AI 先出「题面 + 起始代码 + 一份能跑的参考解」；
2. 再让 AI 照着这份参考解配测试输入；
3. 后端拿参考解**在沙箱里真跑一遍**，全部通过才把题发给你，否则换一批重试（最多 3 次）。

因此**生成需要等 20 秒到 2 分钟**，按钮上会显示真实等待秒数——不是卡住了。
出题失败会明确告诉你原因，不会给你一道自己都跑不通的题。

**答题**：

| 题型 | 怎么答 |
| --- | --- |
| 上机编程（Java/Python/C++/JS/Go） | 在网页 IDE 里写完整程序，读标准输入、写标准输出 |
| 数据库题 | 写 SQL 查询（方言是 **SQLite**），题面下方会给出建表语句与数据 |
| 编程填空 | 代码里用 `{{1}} {{2}}` 标出空位，在下方输入框逐空填写 |
| 选择题 | 勾选选项（可多选） |
| 简答题 | 文本作答，由模型按参考要点评分 |

每道题有两个按钮，区别很重要：

- **运行示例**：只跑题面里展示给你的那几条示例，**不写入记录**，适合边写边调；
- **提交本题**：跑**全部**用例（包含隐藏边界用例）并计分落库，隐藏用例只会告诉你「第 N 个用例未通过」。

**报告**（`/coding/{id}/report`）：逐题显示状态、通过用例数、得分、耗时，简答题额外给出模型评分与
已覆盖/未覆盖的要点，代码题可以展开查看你提交的内容。客观题按通过用例比例计分，所以
「3 个用例过了 1 个」就是 33.3 分。

笔试数据与视频练习一样**保留 7 天**，到期自动清理；也可以手动删除整场笔试。

### 5.8 面试官数字人

面试间里的面试官是一位真人形象（同一张照片切出来的多帧素材），会做这些事：

| 状态 | 表现 |
| --- | --- |
| 准备问题 | 静止（闭唇），字幕显示"正在准备这道题…" |
| 朗读问题 | 播放配音，**嘴型随音量大小变化**（声音大嘴张大），右侧声波条同步跳动 |
| 聆听 | 换成"聆听"姿态，等你开始作答 |
| 录制回答 | 换成"录制回答"姿态（闭唇、保持安静） |
| 追问 | 换成"追问"姿态 |
| 语音不可用 | 恢复静止，字幕提示"语音暂不可用，请阅读下方问题" |

配音播完会自动停回闭唇，不会一直张着嘴。浏览器如果拦了自动播放，
字幕会提示"浏览器拦了自动播放，点「重播问题」即可"——点一下就行，不会反复重试。

静止时的几个细节：**会眨眼**（3-5 秒随机一次）、头部有很轻微的摆动、说话时嘴型变化做了平滑，
不会在阈值附近抖动。

**可选：待机循环视频。** 把一段人物坐着呼吸/眨眼的循环短片放到
`web/public/assets/avatar/idle-loop.mp4`，数字人就会在**不说话时循环播放这段视频**（看着更活），
说话时自动切回切帧动画（嘴型要跟着配音走）。**没有这个文件也完全正常**，
组件会静默退回静态帧，不影响任何功能。

**能力边界（这点请如实对外说明）**：嘴型是**按音量大小**分档选的，
它不知道面试官在念哪个字，所以不是"音素级口型同步"。
音量数据读不到时（跨域、浏览器限制）会自动降级成按固定节奏换嘴型，声音不受影响。

### 5.9 换主题色

左侧栏底部有一排色点，点一下整站强调色就换掉，共三种：**松绿**（默认）、**藏青**、**赭橙**。
选择会保存到你的账号上，换台机器登录仍然是你选的颜色（没登录时会记在浏览器本地）。

只有强调色（按钮、选中态、进度、图表）会跟着变，文字与边框仍保持中性灰，
所以三种配色下的可读性是一致的。

### 5.10 我的简历（`/resumes`）

左侧导航「我的简历」是一个**简历库**：简历长期存在你的账号下（不跟录像一样 7 天清掉），
可以反复用来优化和出题。

**录入**有两种方式：上传文件（PDF / Word / txt，先解析出正文给你过目再保存），或者直接粘贴正文。

解析出来的正文**保留原始分行**：小节标题（基本信息 / 项目经验 / 工作经历 / 教育背景 / 掌握技能）、
每条经历、每个字段都各占一行，项目符号统一成 `- `；PDF 里被排版折断的句子会自动接回去
（"…主要运用于iOS和Android平" + "台。" → 一句完整的描述）。所以**解析完请先扫一眼**：
如果看到正文是一整段糊在一起的文字，说明这份文件的文字层有问题（常见于扫描件或排版很特殊的模板），
这时直接粘贴一份纯文本更省事。

**按岗位优化**：填目标岗位与 JD，AI 会把简历改成对这个岗位更有说服力的写法，并给出**逐段对比**——
左边原文、右边优化后，每段都标了改动类型（`rephrase` 改写、`add_detail` 补细节、`keep` 不动）。
你可以只勾选想采纳的段落，点「采用选中段落」写回正文（版本号 +1）；没采纳的段落不会丢，
优化记录一直留在右侧历史里。

**AI 不会替你编数字**：凡是需要你提供的事实（单量、QPS、团队规模、时间等），它留成
`【请补充：订单量级】` 这样的占位符，并在界面里用琥珀色高亮。**投递前请把这些占位符填掉**，
导出的文件里也会是同样的高亮，一眼能看到没填的地方。

**导出**：右上角「导出」下拉里三种格式，内容都是当前版本的正文——

| 格式 | 什么时候用 |
| --- | --- |
| Markdown (.md) | 想继续编辑、或者再喂给别的工具处理 |
| Word (.docx) | **投递前想手动改一改**：.docx 是原生 Word 文档，字体字号都是真的，打开就能编辑 |
| PDF (.pdf) | 直接投递 / 打印：版式不会因为对方电脑缺字体而跑版（中文字体已经内嵌） |

导出走的是登录态接口，链接带 token 才拿得到，不会放在别人能猜到的地址上。

> PDF 里的中文字体：后端会自动找系统字体（Windows 用 SimHei / 微软雅黑，macOS 用苹方，
> Linux 用 Noto CJK）。如果服务器上一个中文字体都没有，会明确报错提示配置
> `resume.export.pdf-font`，而不是导出一份乱码。

## 6. 报告怎么读

每道题给出一个综合分和 5 个维度分：

| 维度 | 含义 |
| --- | --- |
| 内容相关性 | 回答是否扣题 |
| 回答完整度 | 要点是否答全 |
| 专业程度 | 术语与技术细节的准确度 |
| STAR 结构 | 是否按 Situation / Task / Action / Result 组织（项目类问题尤其重要） |
| 回答逻辑 | 表达是否连贯、有条理 |

表达层指标（每题）：

| 指标 | 含义 |
| --- | --- |
| 语速 | 字/分 |
| 停顿 | 次数 + 总时长（秒） |
| 口头禅 | 出现次数 |

另外还会给出**改进建议**（可执行条目）、**优秀回答示例**，以及带时间戳的**可定位证据**。

> 系统只评价**回答内容与表达**，不做人脸识别、情绪判断或「是否自信」这类主观推断。

## 7. 数据与保留

- 录像按 `MEDIA_PROVIDER` 存到本地磁盘（默认 `./data/media`）或 S3 兼容存储；
- 默认**保留 7 天**（`MEDIA_RETENTION_DAYS`），到期自动清理；
- 在界面上删除一场练习，会同时删掉录像与数据库记录（删除后报告返回 404）；
- **简历是例外**：「我的简历」里的简历与优化记录长期保存，只有你自己删除才会消失；
- 未完成作答会缓存在浏览器 `localStorage`，同一账号在别的机器上看不到。

## 8. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 播报没有声音，接口返回 503 | 未配置 Key 或 TTS 合成失败 | 属预期降级：保留字幕继续作答；配置有效 Key 即可恢复语音 |
| 报告一直是 `awaiting_analysis` | 没有可用的分析供应商 | 检查 `Ali_API_KEY` 与 `PRACTICE_ASR_PROVIDER` / `PRACTICE_EVALUATION_PROVIDER` |
| 报告是 `analysis_failed` | 转写或评分失败 | 看报告里的 `analysis.error`（已脱敏），修好后点「重试分析」 |
| 上传返回 415 | 上传的不是视频 | 上传接口要求 `Content-Type` 以 `video/` 开头 |
| 请求返回 401 | token 过期或缺失 | 重新登录 |
| 摄像头打不开 | 权限被拒 / 被别的程序占用 | 在浏览器地址栏检查权限，关掉占用摄像头的软件 |
| 启动报 `NoClassDefFoundError ... CvRequest` | 用了 `mvn -pl consumer spring-boot:run` 但没先装 common | 先执行 `mvn -B install -DskipTests` |
| 启动报 `DashScope API key must be set` | 缺 `Ali_API_KEY` | 在 `.env` 里填一个非空值 |
| PowerShell 下 Maven 报 `Unknown lifecycle phase ".integration=true"` | `-D` 参数被拆分 | 加引号：`mvn -B test "-Ddb.integration=true"` |
| 注册时提示「该用户名已被注册」 | 用户名全局唯一 | 换一个用户名；账号是全局共享的，不区分邮箱 |
| 注册时提示密码长度不足 | 口令至少 6 位 | 换更长一些的密码 |
| 忘记了密码 | 目前没有自助找回 | 联系管理员在库中把该行口令改回明文，登录一次即自动重新哈希 |
| 笔试页提示「代码沙箱未启用」 | `CODE_RUNNER_ENABLED` 为 false（默认值） | 在 `.env` 里设 `CODE_RUNNER_ENABLED=true` 后重启后端（这会在本机执行用户代码，确认环境可控） |
| 出题失败：参考解无法通过校验 | AI 这一批题的质量没过自检（参考解跑不通或没有有效用例） | 直接重试；连续失败可以把题目组合拆小一些（比如一次 2-3 题），单次重试的成功率更高 |
| 第一次选 C++ / Go 跑很久 | 这两个语言的镜像没有预拉（`gcc:13` 约 1.4GB） | 等它拉完，之后就是正常的秒级执行 |
| 提交后「第 N 个用例未通过」但不给输入 | 那是隐藏用例，故意不展示输入输出 | 用「运行示例」对着可见示例调，或对照报告的期望值自己补边界 |
| 导出 PDF 失败，提示「没有可用于 PDF 的中文字体」 | 服务器上没有装中文字体 | 装一个中文字体，或在 `.env` / `application.properties` 里用 `resume.export.pdf-font` 指定 `.ttf` / `.ttc` 文件路径后重启；只想先拿到文件时，改导出 Word 或 Markdown |

### 8.1 运维：指标与死信队列

分析队列的关键指标通过 Prometheus 暴露（与应用同端口、未鉴权，生产请用网关限制来源）：

```bash
curl http://localhost:8088/actuator/prometheus | Select-String analysis_
```

重点看 `analysis_queue_length`（积压）、`analysis_failure_rate`（失败率）、
`analysis_retry_count_total`（重试次数）、`analysis_dlq_size`（死信条数）。

任务重试到上限后会进入死信队列，可以查询并重新入队：

```bash
# 列出自己的死信任务（需要 Bearer token）
curl -H "Authorization: Bearer <token>" http://localhost:8088/api/v1/analysis/dlq

# 重新入队
curl -X POST -H "Authorization: Bearer <token>" \
  http://localhost:8088/api/v1/analysis/dlq/<jobId>/requeue
```

失败任务按指数退避重试（默认 5 秒起、上限 5 分钟），所以看到 `analysis_failed` 时
先排查根因（Key、配额、ffmpeg、网络），再重入队才有意义。

# 错题本需求文档（把没答好的那道题练到过线）

| | |
| --- | --- |
| 状态 | **已实现并验证**（见 [STATUS.md](STATUS.md) 2026-10-16、迁移 `V10`） |
| 目标 | 让"复盘"落到**具体一道题**上，并且重练一次就有结论 |
| 关联 | [PRACTICE-ARCHIVE-REQUIREMENTS.md](PRACTICE-ARCHIVE-REQUIREMENTS.md)、[COST-GUARD-REQUIREMENTS.md](COST-GUARD-REQUIREMENTS.md)、[USER-GUIDE.md](USER-GUIDE.md) |

---

## 1. 为什么要做

训练档案解决了"**哪一维弱**"（跨场次的维度平均），但它回答不了用户最想问的那句话：

> "那我到底该**再练哪道题**？"

而且有个更难堪的事实：报告里的低分题，**7 天后连题面都不存在了** —— 录像、转写、题目
（`practice_sessions.questions_json`）一起被保留期清理，成绩档案里只有分数和 `question_id`。
所以"重练那道题"在当时是做不到的：分数记得住，题记不住。

一句话：**知道哪里弱，却没有可以立刻再练一次的具体题目。**

---

## 2. 范围

### 2.1 本期做

1. **题干跟着成绩长期保留**：成绩档案新增题面与题目类型（迁移 `V10`），并回填还在保留期内的历史记录；
2. **错题判定**："同一道题的**最好一次**都没到 75 分"才算错题 —— 练过线就自动出本，不需要额外的"我学会了"按钮；
3. **按题目去重**：同一道题重练几次都算同一道，列表上显示"已重练 N 次"；
4. **一键重练**：直接建一场**只有这一道题**的练习（题面就是原来那道），沿用原场次的面试类型/风格/难度；
5. **追问不算错题**：追问是同一道题的延伸，重练原题才有意义（按 `question_category` 排除）。

### 2.2 刻意不做

| 决定 | 原因 |
| --- | --- |
| 不做"学会了"手动标记 | 分数自己会说话：过线即出本，少一个会忘记点的按钮 |
| 不重排出题（不用 AI 再生成一道同类型题） | 用户要练的是**这道题**，不是"这个岗位的题"；顺带省一次模型调用 |
| 不做错题本的分页/筛选 | 一期最多显示 5 条（`limit` 上限 20），先让"练完再回来"这个循环跑通 |
| 不做跨账号对比 | 练习数据只对本人可见（与现有隔离口径一致） |

## 3. 功能需求（FR-10）

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-10.1 | 题面随成绩长期保留 | 评分完成时把题面与题目类型写进成绩档案；场次过期被清理后，错题本仍能显示完整题干 |
| FR-10.2 | 回填历史 | 迁移里从 `practice_sessions.questions_json` 按 `question_id` 回填；保留期外已清理的场次补不回来，如实留空（前端显示"这道题没有保存题干"） |
| FR-10.3 | 错题判定 | 同一道题所有记录里**最好的一次** < 75 分才算错题；阈值与训练档案的短板阈值一致 |
| FR-10.4 | 去重与次数 | 按 `question_id` 分组；显示重练次数（"还没重练过" / "已重练 N 次"） |
| FR-10.5 | 排序与截断 | 最差的排最前面；`limit` 只截显示条数，**总数照实返回**（前端提示"还有 N 道"） |
| FR-10.6 | 指出栽在哪一维 | 每条错题给出该题各维度平均里最低的那一项（哪个维度都没分时留空） |
| FR-10.7 | 追问不进错题本 | `question_category = follow_up` 的记录不参与错题判定 |
| FR-10.8 | 一键重练 | `POST /practice-archive/mistakes/{questionId}/retry` 建一场单题练习：`questionCount = 1`、题目 id 与题面沿用原题、面试类型/风格/难度沿用原场次、默认开追问 |
| FR-10.9 | 无题面不重练 | 没有题面的旧记录返回 404，而不是给用户一道空题 |
| FR-10.10 | 隔离 | 只能看/重练自己的错题；未登录 401 |

## 4. 数据与接口

**迁移 `V10`**（`consumer/src/main/resources/db/migration/V10__mistake_book.sql`）：

```sql
ALTER TABLE practice_score_archive ADD COLUMN question_text      TEXT;
ALTER TABLE practice_score_archive ADD COLUMN question_category  VARCHAR(100);
ALTER TABLE practice_score_archive ADD COLUMN interview_type     VARCHAR(32);
ALTER TABLE practice_score_archive ADD COLUMN interviewer_style  VARCHAR(32);
-- 回填还没被清理的场次，并建 (owner_id, question_id) 索引
```

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/practice-archive/mistakes?limit=5` | 返回 `{scopeNote, passThreshold, total, mistakes[]}`；`limit` 限定 1-20 |
| `POST` | `/api/v1/practice-archive/mistakes/{questionId}/retry` | 建出单题练习，返回正常的 `PracticeSessionView`（201） |

重练返回的就是一场普通练习，所以前端拿到 id 后走的是**原有链路**：设备检测 → 录制 → 报告。
不为新功能另写一套界面，是这次刻意省下来的复杂度。

## 5. 前端设计

- 位置：`/`（训练总览）的"训练档案"**下面**，同一条动线上（先看趋势，再看具体哪道题）；
- 每行：分数（橙色）／"还差 X 分"／题干／分类标签 · 岗位 · 难度 · 主要栽在哪个维度 · 重练次数／「重练这道题」；
- 没有错题时不显示这一块（不制造"你这里空着"的焦虑）；
- 超过显示条数时一行灰字提示还有几道。

## 7. 已知限制

1. **升级前的旧成绩补不回题面**：题面只存在场次的 `questions_json` 里，场次被清理就等于永久丢失。
   想彻底避免，只能从这次升级开始往后积累（这也是为什么"题干跟着成绩走"要写进档案）。
2. **重练只是"再练一次"**，不保证分数一定上升 —— 但列表上"还差 X 分"和重练次数至少让变化看得见。
3. 错题本目前只看**视频练习**；笔试的错题（哪道题没过用例）还没有进本。

# 产品需求与优化建议报告

## 评审依据

本轮实际打开登录/注册页面，确认了系统路由入口和后端接口目录；后端健康为 UP，未登录访问业务 API 返回 401。由于没有专用账号和可执行的 E2E 浏览器，登录后的练习、报告和历史闭环未能通过真实用户操作验证。以下建议只基于已观察到的界面、代码路由和 API 能力，未把未验证内容当作事实。

## A. 必要改进

### REQ-001 让测试与演示环境可一键验证

- 当前情况及证据：前端依赖 Playwright，但浏览器二进制缺失；Vitest 执行因 esbuild `spawn EPERM` 失败；文档依赖演示账号/环境变量。
- 用户痛点：新贡献者、QA 和发布人员无法快速复现核心流程，质量结论依赖人工准备。
- 建议方案：提供固定 Node LTS/浏览器版本、`npm run e2e:install`、健康检查和隔离测试数据库初始化；测试账号只在 test profile 创建。
- 目标用户：QA、开发者、维护者。
- 用户价值：把“无法验证”变为可重复证据，降低回归风险。
- 优先级：P0；复杂度：中。
- 验收标准：干净环境执行三条命令可启动前后端、运行 smoke/E2E；失败自动保存截图、console 和网络日志；不触碰默认开发数据。
- 关联及影响：关联现有 `web/package.json`、Playwright 依赖、`scripts/smoke-test.ps1`；主要影响 CI/开发脚本。

### REQ-002 提供明确的后端根地址与统一错误响应

- 当前情况及证据：GET `/actuator/health` 返回 200，GET `/` 返回 404；多个未授权 API 为 401，但代码笔试能力接口的 PowerShell 检查未获得一致响应。
- 用户痛点：部署检查和前端故障排查时无法区分服务存活、路由错误和认证失败。
- 建议方案：根路径返回服务名/版本/文档链接或 302 到健康页；统一认证错误 JSON schema 和 correlation id。
- 目标用户：最终用户、运维、前端开发者。
- 用户价值：减少误判和无效排障。
- 优先级：P1；复杂度：低。
- 验收标准：`/`、`/actuator/health`、所有受保护 API 的响应契约在文档和自动化测试中一致。
- 关联及影响：关联 Spring Controller/异常处理和部署文档；不改变业务权限。

## B. 体验优化

### REQ-003 首次登录页增加“先做什么”的可操作引导

- 当前情况及证据：登录页文案强调“目标岗位”“视频模拟面试”，但本轮可见入口只有登录/注册；忘记密码提示为“联系管理员重置”。
- 用户痛点：新用户不知道注册后第一步是设置目标、上传简历还是直接开始练习；忘记密码没有自助路径。
- 建议方案：注册成功后进入三步引导（目标岗位/简历/首次练习），提供跳过与返回；增加邮箱验证后的找回密码，或明确管理员入口与响应时效。
- 目标用户：首次使用者。
- 用户价值：缩短首次价值实现时间，降低流失。
- 优先级：P1；复杂度：中。
- 验收标准：新账号在 3 分钟内能到达首次练习；每步可跳过；失败可恢复；密码找回不泄露账号是否存在。
- 关联及影响：关联 LoginView、目标/简历/Setup 路由；会增加 onboarding 状态。

### REQ-004 面试会话增加明确的状态、保存和恢复反馈

- 当前情况及证据：路由包含设备检查、session、retake、report，后端包含 pause、answer complete、media、analysis retry 等接口，但本轮无法完成登录后验证。
- 用户痛点：录音、上传、AI 分析耗时较长时，用户可能不知道是否已保存、能否离开或如何恢复。
- 建议方案：统一显示“录制中/上传中/已保存/分析中/失败可重试”；离开页面前提示未完成上传；会话页提供断点恢复入口。
- 目标用户：练习面试的求职者。
- 用户价值：降低丢失回答和重复录制焦虑。
- 优先级：P1；复杂度：中。
- 验收标准：模拟网络失败、刷新和重复点击后，状态可解释且不会生成重复回答；上传失败可重试并保留进度。
- 关联及影响：关联 PracticeSessionController、ChunkUploadController、SessionView；需端到端状态契约。

### REQ-005 报告与历史记录形成可比较的学习闭环

- 当前情况及证据：代码路由包含 report、history、mistakes、weekly report、retake，后端也有 archive/mistakes/progress 接口；登录后内容未能验证。
- 用户痛点：用户需要知道本次反馈如何转化为下一次练习，以及不同日期/岗位的进步趋势。
- 建议方案：报告页固定展示三项最重要改进、对应错题/重练按钮和前后版本对比；历史支持岗位、日期、分数、状态筛选。
- 目标用户：持续练习用户。
- 用户价值：把一次性评分转成可执行复习计划。
- 优先级：P1；复杂度：中。
- 验收标准：完成一次练习后可从报告进入错题重练；历史筛选结果与详情一致；删除/保留策略清晰。
- 关联及影响：关联 ReportView、HistoryView、MistakeBookView、WeeklyReportView 和 archive API。

## C. 新增功能

### REQ-006 增加“无 AI/无摄像头”降级练习模式

- 当前情况及证据：配置支持 stub ASR/evaluation，前端存在语言、代码和视频练习入口；本轮真实 AI/媒体不可验证。
- 用户痛点：网络、权限或额度异常时，用户无法继续训练。
- 建议方案：允许纯文本回答和本地计时练习，明确标注“未使用真实 AI 评分”；服务恢复后可重新提交分析。
- 目标用户：设备受限、网络不稳定或希望先熟悉流程的用户。
- 用户价值：提升可用性和新手试用转化。
- 优先级：P2；复杂度：中。
- 验收标准：摄像头/麦克风拒绝后仍能完成文本流程；评分结果明确区分模拟/真实；不伪造 AI 已完成。
- 关联及影响：关联 provider 配置、SessionView、分析状态接口；需产品明确评分标签。

### REQ-007 增加面试流程可访问性与键盘操作检查

- 当前情况及证据：登录页已有 role=tab、aria-selected，说明系统已使用部分语义化控件；完整页面无实际无障碍审计证据。
- 用户痛点：键盘用户、低视力用户或移动设备用户可能无法完成录制和报告浏览。
- 建议方案：建立页面级键盘顺序、焦点可见、错误关联、字幕/文本替代和对比度验收项。
- 目标用户：所有需要辅助技术的用户。
- 用户价值：扩大可用人群，减少表单误操作。
- 优先级：P2；复杂度：中。
- 验收标准：核心流程仅用键盘可完成；表单错误可被读屏关联；录音/视频提供文本替代或转写。
- 关联及影响：关联所有主要 View 与 DigitalHuman；可能需要组件层规范。

## 最值得优先考虑的五项建议

1. REQ-001：让测试与演示环境可一键验证。
2. REQ-004：面试会话状态、保存和恢复反馈。
3. REQ-005：报告与历史形成可比较的学习闭环。
4. REQ-003：注册后的首次使用引导与密码找回。
5. REQ-002：后端根地址与统一错误响应。

## 评审边界

本报告没有把“未验证”写成产品缺陷；REQ-004/005 的当前痛点需要在具备测试账号后通过实际会话进一步确认。REQ-006/007 属于新增能力或体验规范，建议在核心链路可稳定回归后排期。

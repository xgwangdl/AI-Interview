## 2. 缺陷修复

### FIX-001 分片合并使用客户端 totalBytes

- 对应：CR-001。
- 根因：`ChunkedUploadService.merge()` 把 `MediaMergeRequest.totalBytes` 直接传给媒体入库。
- 修复：合并前读取所有分片，计算真实字节数和 SHA-256；声明值与真实值不一致返回 400。
- 入库和日志只使用服务端实际值。
- 回归：`ChunkedUploadServiceTest`、`scripts/verify-chunked-upload.ps1`。

### FIX-002 非法媒体延迟失败

- 对应：BUG-005。
- 根因：上传接口只检查 `video/*` Content-Type，不检查文件内容和长度。
- 修复：新增 `MediaSignatureValidator`，单段与分片共用。
- 支持 WebM/Matroska、MP4/MOV、Ogg、AVI、FLV；小于 256 字节或未知签名在 HTTP 上传阶段拒绝。
- 前端收到 400/415 时要求重新录制，不再把同一坏文件标记为可补传。
- 边界：该检查是快速容器校验，不解码整段视频；合法容器头但内部损坏仍可能由 FFmpeg/ASR 后续报错。

### FIX-003 FFmpeg 可发现性

- 对应：CR-002。
- 根因：`AudioConverter` 使用静态方法和固定 Windows 路径，且运行镜像未安装 ffmpeg。
- 修复：
  - 改为 Spring 组件。
  - 默认执行 `ffmpeg`，从 PATH 查找。
  - `FFMPEG_PATH` 可通过 `.env` 覆盖。
  - 缺失可执行文件时返回可操作错误。
  - Docker 运行镜像安装 ffmpeg。
- 回归：`AudioConverterTest`；Docker 镜像内 `ffmpeg -version` 实测为 8.1.2。

### FIX-004 ASR 异常被吞

- 对应：CR-003。
- 根因：`SpeechToTextService` 捕获所有异常后返回空字符串。
- 修复：供应商调用、JSON 解析、缺失 sentences、空列表、空文本分别抛 `IOException`。
- 回归：`SpeechToTextServiceTest` 覆盖正常结果、供应商异常、缺失句段和非法 JSON。

### FIX-005 根路径 404

- 对应：BUG-003、REQ-002。
- 修复：新增 `ServiceInfoController`，`GET /` 返回服务名、状态、版本、健康入口、API 前缀和 ffmpeg 可用性。
- 不暴露密钥、数据库连接和用户数据。

### FIX-006 笔试 capabilities 鉴权

- 对应：BUG-004。
- 实际核查：原接口不是异常，而是明确返回公开 200。
- 决定：能力信息虽不敏感，但为保持 `/api/v1` 业务契约一致，改为要求 Bearer Token。
- 回归：未登录返回统一 401；登录后响应结构不变。

### TEST-001 测试可复现性

- BUG-001 的 esbuild `spawn EPERM` 是当前本地沙箱执行限制；在受控执行下前端 145 个测试通过。
- BUG-002 的 Playwright 自带浏览器缺失不再是唯一路径；新增 `npm run test:e2e`，优先使用系统 Chrome/Edge。
- CI 安装固定 Chromium 后执行认证 UI E2E。

## 3. 产品需求处理

### 本轮实施

- 核心失败前置：非法媒体在上传时明确拒绝。
- 失败语义：服务器明确拒绝与网络暂时失败分开处理。
- 部署可观测性：根路径服务信息和 ffmpeg 状态。
- 测试闭环：认证 E2E 和媒体安全脚本。

### 已存在，未重复开发

- 首页目标/今日训练。
- 面试录制、保存和分析状态展示。
- 报告改进建议、分析重试、改写与重录。
- 历史岗位/状态筛选。
- 错题本一键重练和周报。

### 暂缓

- 注册后三步 onboarding：现有首页已有目标与今日训练入口，新增向导需要新状态模型和真实用户验证。
- 无摄像头纯文本降级：需要调整会话与评分契约，当前优先稳定真实媒体链路。
- 全面无障碍：需要逐页键盘、焦点、读屏和对比度审计。
- 会员、第三方登录和更复杂社群：与当前“先稳定单场景核心闭环”的市场阶段不符。

## 5. 兼容性与数据影响

- 无数据库结构变更。
- 已有媒体和练习数据不迁移、不删除。
- 正常前端已经发送正确 `totalBytes`，分片合并行为兼容。
- 小于 256 字节或非视频容器的新上传会被拒绝；正常浏览器录像不受影响。
- coding capabilities 从匿名 200 变为未登录 401；登录态响应不变。
- `.env` 不需要强制设置 `FFMPEG_PATH`；未设置时从 PATH 查找。

## 6. 未解决与残余风险

- 真实 ASR + 评分在 60 秒测试窗口内仍可能保持 pending；本轮没有把该链路标记为成功。
- 容器签名检查不是完整解码；损坏的合法视频仍可能在分析阶段失败。
- 已有非法媒体历史数据未主动清理。
- 真实摄像头、麦克风权限拒绝和断网恢复仍需浏览器人工/专项测试。
- 代码沙箱的完整 Docker 语言矩阵没有在本轮重新执行。

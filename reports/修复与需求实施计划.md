## 4. 实施顺序

### 第一优先级：核心链路可靠性

1. **FIX-001**
   - 合并前统计分片真实字节数。
   - 与 `request.totalBytes` 不一致时返回 400。
   - 入库和日志一律使用真实值。
   - 测试：少报、多报、0/负数、正常合并。

2. **FIX-002**
   - 增加媒体文件签名与最小长度校验。
   - 覆盖 WebM/Matroska、MP4/MOV、Ogg、AVI、FLV。
   - 单段上传和分片合并共用同一校验。
   - 非法媒体在 HTTP 上传阶段返回明确 4xx，不进入分析队列。
   - 测试：17 字节占位内容、未知签名、合法 WebM 头。

3. **FIX-003**
   - `AudioConverter` 改为 Spring 组件，读取 `FFMPEG_PATH`，默认使用 PATH 中的 `ffmpeg`。
   - Docker 运行镜像安装 ffmpeg。
   - 错误信息区分“未找到可执行文件”和“媒体转换失败”。
   - 测试：缺失可执行文件时给出可操作错误。

4. **FIX-004**
   - ASR 调用、JSON 解析、空句子、空文本分别抛出 `IOException`。
   - 不再打印供应商响应栈到标准输出。
   - 测试：正常响应、缺失 `sentences`、空列表、空白文本、调用异常。

### 第二优先级：API 与可验证性

5. **FIX-005**
   - 新增根路径响应：服务名、状态、健康入口、版本和 ffmpeg 可用性。
   - 不暴露密钥、数据库地址或用户数据。

6. **FIX-006**
   - `GET /api/v1/coding-sessions/capabilities` 要求 Bearer Token。
   - 保持响应结构不变。

7. **TEST-001**
   - 新增跨平台浏览器认证冒烟命令。
   - 覆盖登录页、注册页、空值提示、未登录路由重定向。
   - 本地优先使用系统 Chrome，CI/已安装浏览器环境可用 Playwright 浏览器。

## 5. 验收标准

- `mvn -B test` 全部通过；新增缺陷均有回归测试。
- `npm --prefix web test` 与 `npm --prefix web run build` 通过。
- 根路径返回结构化 JSON，健康检查仍为 UP。
- 未认证访问 coding capabilities 返回统一 401 JSON。
- 分片上传伪造 `totalBytes` 返回 400。
- 17 字节非法媒体在上传接口立即被拒绝。
- 合法 WebM/MP4 上传路径不被破坏。
- ffmpeg 缺失时错误可操作，Docker 镜像内可通过 PATH 找到 ffmpeg。
- 浏览器认证冒烟可执行并保存截图证据。

## 6. 潜在影响

- 旧的异常媒体文件不会自动删除；本次只阻止新非法上传。
- 已有合法媒体元数据保持不变，无数据库迁移。
- 分片客户端必须提供正确 `totalBytes`；当前前端已经提供，因此正常流程不受影响。
- 如果已有客户端依赖未认证的 capabilities，需要先登录后调用；前端现有 `apiRequest` 已自动携带 token。
- 低码率、极短但合法录像可能小于最小长度阈值；阈值设置为保守的 256 字节，仅用于拦截明显占位文件。
